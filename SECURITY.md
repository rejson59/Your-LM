# Bezpieczeństwo YourLM

## Co wykonuje wydanie Windows

`YourLM.exe` uruchamia lokalny panel HTTP wyłącznie na losowym porcie `127.0.0.1` i pokazuje go w natywnym oknie WebView2; systemowe `ShellExecuteW` otwiera przeglądarkę tylko awaryjnie. Po wyborze modelu aplikacja uruchamia prywatnie rozpakowany `llama-server.exe`. Opcjonalny tryb workera uruchamia `ggml-rpc-server.exe` tylko na loopbacku; do sieci prywatnej wystawiany jest oddzielny tunel TLS. Android udostępnia ten sam uwierzytelniony most TLS również na osobnym loopbacku przeznaczonym dla lokalnego `adb forward`; ADB nigdy nie wskazuje bezpośrednio surowego portu RPC. QR przenosi odcisk certyfikatu i sekret sesji. Ręczne parowanie używa 100-bitowego kodu, który nie jest wysyłany: host weryfikuje HMAC losowego wyzwania, adresu i odcisku certyfikatu, po czym przypina certyfikat dla właściwego tunelu TLS.

Pojedynczy EXE zawiera skompresowany runtime, minimalny ADB i APK. Przy starcie rozpakowuje wersjonowaną kopię do zarządzanego katalogu `components`, porównuje ją z osadzonym payloadem i odtwarza brakujące albo zmienione pliki. SHA-256 runtime jest dodatkowo sprawdzany bezpośrednio przed każdym uruchomieniem. ADB działa tylko na żądanie użytkownika do wykrycia telefonu, lokalnej inwentaryzacji/testu, `adb install -r` oraz dynamicznego przekierowania loopback podczas uwierzytelnionego pomiaru/transportu USB. Test pamięci tworzy wyłącznie nazwany plik tymczasowy `/data/local/tmp/yourlm-storage-benchmark.tmp`, po czym go usuwa. YourLM usuwa tylko ten plik i przekierowania, które sam utworzył; nie wywołuje globalnego `forward --remove-all`.

Przy pierwszym uruchomieniu wydaniowy EXE wybiera `D:\YourLM` tylko wtedy, gdy D: jest zapisywalnym dyskiem stałym z bezpiecznym zapasem pojemności. Kopiuje program do `D:\YourLM\App`, a dane do `D:\YourLM\Data`. Migrację chroni nieblokujący lock systemu operacyjnego, a osobny lock instancji pozostaje otwarty przez całą sesję — także po fallbacku na C:. Drugi proces nie dostaje prawa do równoległej publikacji ani do pracy na źródle pod aktywnym pierwszym oknem; oba locki po wyjściu lub awarii zwalniają się automatycznie. Istniejący `.migrating-part` jest zwykłym plikiem tylko wtedy, gdy przejdzie kontrolę typu, rozmiaru i całego prefiksu względem źródła. Prawidłowy prefiks jest dopisywany i synchronizowany, wadliwy plik etapowy jest odrzucany pojedynczo, a niemożliwy do odczytu lub zablokowany zatrzymuje operację bez naruszania C:. Wszystkie pliki oraz dokładne drzewo są ponownie porównywane przez SHA-256; znacznik gotowości powstaje dopiero po tej kontroli, a atomowe `Data.migrating` → `Data` jest jedyną publikacją. Dopiero potem źródło jest atomowo odkładane i usuwane. Jeżeli źródło pozostało po nieudanym sprzątaniu, następny start ponownie porównuje je plik po pliku z opublikowanym D:, zamiast ufać samemu znacznikowi. Gdy drzewa się różnią, RC19 tworzy wyłącznie w nieaktywnym stagingu ich sumę: aktywne C: jest autorytatywne dla kolidującej ścieżki, a wpisy istniejące tylko na D: są zachowywane. Każdy wynikowy plik jest sprawdzany SHA-256 przed zapisaniem znacznika `reconciled`; stare D: trafia do `Data.reconcile-backup`, staging jest publikowany atomowo, a opublikowany manifest jest liczony ponownie przed sprzątnięciem rollbacku i C:. Przerwanie przed publikacją przywraca poprzednie D:, natomiast uszkodzona nowa publikacja nie może usunąć rollbacku. Jeśli wycofanie C: jest zablokowane już po pełnej publikacji, strukturalny znacznik zapisuje je jako nieaktywną kopię do sprzątnięcia, aby następny start nie nałożył jej na później zmodyfikowane D:. Dowiązanie lub specjalny wpis zatrzymuje operację; każde usuwane poddrzewo jest najpierw w całości odwiedzane i walidowane. Nieopublikowane staging, uszkodzony znacznik i obca zawartość nigdy nie są używane jako biblioteka. Przy braku odpowiedniego D: pozostają dotychczasowe ścieżki `%LocalAppData%\Programs\YourLM` i `%AppData%\YourLM`. Program tworzy skrót w Menu Start i zapisuje wpis odinstalowania `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\YourLM` oraz wybór zarządzanego magazynu w `HKCU\Software\YourLM`. Do utworzenia `.lnk`, wycofania starego EXE i odinstalowania używa wbudowanego Windows PowerShell i lokalnego COM `WScript.Shell`; nie pobiera ani nie wykonuje skryptu z sieci. Nie instaluje usługi, sterownika ani autostartu, nie wymaga administratora i nie dodaje wyjątków antywirusowych. `--portable` wyłącza rejestrację aplikacji. Odinstalowanie usuwa EXE, skrót i wpis odinstalowania, ale zachowuje zarządzany magazyn z modelami i logami.

Kontroler sprawdza publiczne wydania GitHub. Nowy `YourLM.exe` pobiera do prywatnego katalogu aktualizacji, ogranicza jego rozmiar i weryfikuje digest SHA-256 podany przez GitHub, po czym uruchamia nowy EXE jako jednorazowy helper podmiany. Helper czeka na rzeczywiste zakończenie poprzedniego procesu (a więc także zwolnienie blokady magazynu), zanim podmieni plik i uruchomi nową wersję. Android pobiera wyłącznie asset `YourLM-Android-arm64.apk`, sprawdza digest, nazwę pakietu i nowszą wersję, a instalację zawsze przekazuje systemowemu ekranowi potwierdzenia.

Kontroler usuwa ze środowiska procesu potomnego zmienne `LLAMA_*` i `GGML_*`, które mogłyby włączyć inne zachowanie. Jawnie uruchamia `llama-server` w trybie offline, bez Web UI, MCP proxy i wbudowanych narzędzi plikowych/powłoki. Narzędzia agenta Continue działają po stronie Continue i nie wymagają serwerowych narzędzi `llama.cpp`.

Autopilot RC19 nie jest zdalnym pulpitem ani autonomicznym administratorem. Może odczytać ograniczone metadane sprzętu, utworzyć i usunąć własne próbki benchmarku, przenieść wyłącznie zarządzany katalog YourLM oraz — po widocznym potwierdzeniu — uruchomić przypięte pobieranie modelu. Nie przyjmuje arbitralnych poleceń powłoki, nie skanuje dokumentów użytkownika, nie wyłącza zabezpieczeń i nie omija systemowego potwierdzenia instalacji Androida. Krótki raport wsparcia celowo pomija nazwę hosta, numer seryjny ADB, sekret parowania i klucz API oraz redukuje powtarzalne transfery tensorów i stare stosy wyjątków; pełny lokalny log pozostaje na dysku pod pokazaną ścieżką, a osobny przycisk kopiuje rozszerzony wariant.

Runtime powstaje z dokładnie przypiętego commita `llama.cpp` oraz śledzonej w repozytorium poprawki RPC. Skrypt odmawia budowania, jeśli patch nie pasuje do źródła. Na Linuxie i Androidzie poprawka przekazuje planiście rzeczywiste `MemAvailable`, zamiast uznawać cały fizyczny RAM za wolny; dodatkowy bezpiecznik hosta kończy ładowanie po trzech kolejnych pomiarach workera poniżej 1 GiB. Cache workera jest prywatny dla aplikacji; wpis jest publikowany dopiero po pełnym zapisie, przy odczycie ponownie sprawdzany jest rozmiar i hash, a osierocone pliki tymczasowe są usuwane przed następnym startem.

Poza sprawdzaniem/pobraniem aktualizacji z `api.github.com` i adresu assetu GitHub kontroler łączy się tylko z lokalnym serwerem modelu oraz ze sparowanymi prywatnymi adresami IPv4. Kod nie zawiera telemetrii. API modelu może zostać świadomie wystawione jako HTTP w prywatnym LAN; domyślnie słucha tylko na `127.0.0.1`.

## Granice zaufania

- GGUF i programy runtime są przetwarzane przez `llama.cpp`; używaj wag z zaufanego źródła.
- QR i krótki kod parowania są sekretami jednorazowej sesji. Nie publikuj ich. Krótki kod ma cztery grupy po pięć znaków i 100 bitów losowości; nie jest to sześciocyfrowy PIN.
- Surowy protokół RPC jest eksperymentalny i dlatego nigdy nie słucha bezpośrednio w LAN.
- Aplikacja nie chroni przed złośliwym programem już działającym na tym samym koncie Windows lub Android.
- Wydanie testowe nie ma komercyjnego podpisu Authenticode. Suma i jawny kod pozwalają zweryfikować artefakt, ale nie zastępują reputacji podpisanego wydawcy.
- Bramka publikacji `.github/workflows/release.yml` skupia się na działaniu produktu: buduje przypięte silniki, sprawdza zgodność pakietów, uruchamia EXE oraz wykonuje przepływy workera, parowania i hosta Android.

## Zgłaszanie

Nie publikuj sekretów sesji ani danych modelu. Problem bezpieczeństwa opisz w prywatnym zgłoszeniu GitHub Security Advisory repozytorium. Podaj wersję, system, kroki reprodukcji i — w przypadku alarmu antywirusa — pełną nazwę wykrycia oraz SHA-256. Nie wyłączaj antywirusa i nie dodawaj wyjątku na potrzeby testu.
