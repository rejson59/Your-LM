# YourLM — prywatny klaster GGUF

**0.2.0-rc15 · Qwen3.6-35B-A3B Abliterated Balanced Q2/Q4 · izolowany pager ekspertów Android · stabilny Windows/RPC · Android ARM64 (9+)**

YourLM uruchamia `llama.cpp` na CPU i potrafi przenieść część warstw modelu na inne urządzenia. To jedna inferencja z podziałem warstw, a nie rozsyłanie całego pytania do kilku niezależnych chatbotów. Nie wymaga konta, chmury ani roota. Aplikacja nie dodaje własnego filtra treści; zachowanie zależy od modelu i jego szablonu czatu.

Gotowe pliki są publikowane na stronie [GitHub Releases](https://github.com/rejson59/Your-LM/releases):

| Gotowy plik | Do czego służy |
|---|---|
| `YourLM.exe` | Samodzielna aplikacja Windows. Silnik, ADB i APK są w środku; pierwszy start instaluje ją per-user i dodaje do Menu Start. |
| `YourLM-Android-arm64.apk` | APK na Redmi lub inny zgodny ARM64. Worker, samodzielny czat lub host klastra. |
| `SHA256SUMS` | Sumy kontrolne plików wydania. |

**Modele nie są dołączone.** Ekran Model proponuje jeden środek: **Qwen3.6-35B-A3B Abliterated · Balanced Q2/Q4**. YourLM składa go lokalnie z przypiętych Q4_K/Q2_K tego samego checkpointu Huihui, sprawdza pełny schemat i metadane, zapisuje ekspertów na końcu dla pagera oraz wylicza SHA-256 gotowego pliku. Abliteracja ogranicza wyuczone odmowy — nie zwiększa inteligencji. Inny jednoplikowy, tekstowy GGUF typu *instruct/chat* można nadal wskazać ręcznie, na licencji odpowiedniej do zastosowania. [Dokładna receptura i ograniczenia](docs/QWEN36-BALANCED.md). Panel, skaner QR i czat działają lokalnie. Pierwszy start EXE kopiuje aplikację do `%LocalAppData%\Programs\YourLM\`, dodaje ją do Menu Start i rozpakowuje przypięty runtime oraz minimalny ADB do prywatnego `%AppData%\YourLM\`; pliki są sprawdzane i automatycznie odtwarzane przy uszkodzeniu. Instalacja jest per-user, bez administratora. Internet jest używany tylko do jawnie uruchomionego sprawdzania aktualizacji albo wyszukiwania/pobierania wybranego publicznego GGUF z Hugging Face — nigdy do inferencji ani wysyłania promptów.

## Pierwsze uruchomienie: Lenovo + Redmi

1. **Najpierw sam laptop.** Pobierz `YourLM.exe` i uruchom jako zwykły użytkownik — nigdy jako administrator. Niczego nie wypakowuj. YourLM zainstaluje się dla bieżącego użytkownika, pojawi się w Menu Start oraz w Ustawieniach Windows i otworzy panel w natywnym oknie WebView2. Pobrany plik z folderu Pobrane można później usunąć. Parametr `--portable` świadomie pomija instalację. Przeglądarka jest wyłącznie awaryjnym fallbackiem, gdy środowisko WebView2 jest niedostępne.
2. **Przygotuj pamięć i wybierz Balanced.** W Urządzenia → „Odzyskaj pamięć przed modelem” Windows pokaże zwykłe widoczne aplikacje, ich przybliżony RAM i pozwoli wysłać wybranym standardowe, niewymuszone zamknięcie po zapisaniu pracy. Potem w Model i API wybierz **Zbuduj i wybierz model Balanced**. Pobieranie potrzebnych zakresów Q4_K/Q2_K pokazuje procent, prędkość i ETA, można je zatrzymać bez utraty ukończonych części oraz wznowić. YourLM nie przechowuje dwóch pełnych źródeł. Sprawdź licencję Apache-2.0 modelu. Pozostaw `127.0.0.1`, kliknij **Uruchom model**, poczekaj na „Gotowy” i otwórz **Czat**. Na Windows/RPC działa stabilny b12562; bezpośredni host Android wybiera pager tylko po sprawdzeniu architektury i CPU.
3. **Zainstaluj aplikację na Redmi.** W panelu Windows otwórz **Telefon USB** i wykonaj trzy pokazane kroki. W HyperOS włącz Debugowanie USB oraz, jeśli jest wymagane, **Instalowanie przez USB**. YourLM wykryje urządzenie i użyje `adb install -r`, aby instalować kolejne wersje bez kasowania danych. APK z Releases pozostaje alternatywą; Android zawsze pokazuje systemowe potwierdzenie instalacji. **Po aktualizacji EXE ponów ten krok — Windows nie podmienia samoczynnie już zainstalowanego APK telefonu.**
4. **Dołącz Redmi jako worker.** Zatrzymaj model na laptopie, połącz urządzenia z tym samym prywatnym Wi-Fi i na telefonie wybierz **Pomóż laptopowi → Uruchom worker w tle**. Główny plik GGUF pozostaje na hoście; telefon może przechować w prywatnych danych aplikacji cache przydzielonych tensorów. Telefon pokaże **adres parowania** i 20-znakowy **kod parowania**. Na laptopie wybierz **Urządzenia → Dodaj telefon** i przepisz oba pola. Kamera laptopa jest tylko opcją; telefon niczego nie skanuje. Jeśli debugowanie USB jest autoryzowane, możesz pozostawić kabel: po sparowaniu i przed startem modelu YourLM prześle po 4 MiB w obie strony przez Wi-Fi oraz szyfrowany tunel `adb forward`, a następnie wybierze łącze z lepszym wynikiem ważonym pod transfer host → worker; przy różnicy do 5% rozstrzyga niższy ping.
5. **Uruchom ten sam model ponownie.** Panel pokazuje sześć potwierdzonych etapów startu, czas, bieżący odczyt dysku/CPU oraz transfer do workera. Pasek etapów jest orientacyjny — samodzielny `llama-server` nie udostępnia dokładnego procentu całego startu — ale odróżnia aktywne ładowanie od dłuższego braku mierzalnej pracy i pozwala zatrzymać je bez otwierania surowego logu. Pierwszy transfer przydzielonych wag przez wybrane łącze może trwać długo, ale kolejne uruchomienia tego samego modelu korzystają z cache RPC. Cache jest zapisywany i odczytywany porcjami do 16 MiB, zamiast tworzyć na workerze dodatkową kopię całego dużego tensora. RC12 wylicza rezerwę z największego tensora modelu: co najmniej 2048 MiB, a dla większych tensorów więcej, aby objąć przejściowy szczyt ładowania, Androida, TLS i proces RPC. Worker jest usługą pierwszoplanową z blokadą CPU i Wi-Fi: możesz wyłączyć ekran, wrócić do ekranu głównego lub zamknąć widok aplikacji. Po nieoczekiwanym wyjściu procesu natywnego zachowuje pierwotną diagnostykę i wykonuje najwyżej trzy próby odtworzenia z opóźnieniami 1/5/15 s; nie wpada w nieskończoną pętlę. Żądany stan przetrwa rekreację usługi Androida, natomiast jawne zatrzymanie nigdy nie jest automatycznie cofane. Zatrzymasz go przyciskiem w aplikacji albo stałym powiadomieniem. Przerwij pracę, jeśli telefon się przegrzewa, i zatrzymaj model przed odłączaniem urządzeń.

**Czas odpowiedzi.** Wbudowany czat pokazuje każdy fragment odpowiedzi natychmiast, domyślnie ogranicza szybką próbę do 64 tokenów i pozwala przerwać generowanie bez zatrzymywania całego modelu. USB może znacząco skrócić przesyłanie wag, ale nie zwiększa wydajności CPU. Balanced jest dużym MoE: szybkość, temperatura i szczyt RAM na konkretnym Lenovo/Redmi wymagają pomiaru i nie są obietnicą wydania. MTP pozostaje wyłączone, ponieważ opublikowane próby głębokości 1 i 2 były wolniejsze od bazowej generacji. Ostrzeżenie `removing it from EOG list` oznacza wadliwe metadane tokenu końca konkretnego GGUF — taki model może zawsze generować aż do ustawionego limitu.

**Inne role.** Na drugim Windows uruchom ten sam samodzielny EXE, w zakładce **Urządzenia** rozwiń „Udostępnij ten komputer innemu hostowi”, wybierz prywatny IPv4 i uruchom. Na Androidzie jako host: **Model na telefonie → Dodaj plik GGUF** (systemowy selektor tworzy kopię w prywatnej bibliotece aplikacji) → **Otwórz konsolę** → **Model i API** → wybierz model z biblioteki. Możesz działać bez workerów albo najpierw sparować inne urządzenia. Host i worker to rozłączne role; jeden worker obsługuje jednego hosta naraz. Host obsługuje do ośmiu sparowanych workerów; większe konfiguracje nie były mierzone.

## Ile naprawdę zmieści się w RAM?

- Od rc3 stary statyczny planista został usunięty. Bez workera YourLM jawnie wyłącza fizyczny test `--fit`, aby Windows mógł podjąć próbę uruchomienia dużego GGUF przez file-backed mmap nawet wtedy, gdy plik jest większy od fizycznego RAM-u.
- Z workerami YourLM używa natywnego, tensorowego `llama.cpp --fit-target`: host odczytuje rozmiar największego tensora, dodaje konserwatywną rezerwę na szczyt jego odbioru, docelowego bufora i zapisu cache, po czym przekazuje co najmniej 2048 MiB; runtime ponownie mierzy backendy i trzyma pozostałe wagi w mmap hosta. YourLM nie narzuca `-ngl` ani `--tensor-split`.
- Przy autoryzowanym fizycznym USB Windows tworzy wyłącznie lokalny `adb forward` do dodatkowego, przypiętego certyfikatem mostu TLS na loopbacku Androida. Surowy port RPC nadal nie jest wystawiany. YourLM mierzy osobno wysyłanie i odbiór 4 MiB przez USB i Wi-Fi, mocniej waży kierunek host → worker, pokazuje oba wyniki oraz zachowuje drugie łącze jako awaryjne. Dobre Wi-Fi 5 GHz może wygrać z USB 2.0; test nie zwiększa mocy CPU telefonu.
- Przed startem karta **Odzyskaj pamięć** może zsumować procesy potomne widocznych aplikacji Windows i wysłać wyłącznie `WM_CLOSE` do zaznaczonych pozycji; największe bezpieczne aplikacje są zaznaczone wstępnie i można je odznaczyć. Nie używa `TerminateProcess`; chroni system, instalatory, terminale, antywirusa, aplikacje administratora i YourLM. Android bez roota nie może niezawodnie zamknąć cudzych aplikacji, dlatego natywna karta otwiera systemową listę aplikacji i pozwala odświeżyć pomiar bez nowych inwazyjnych uprawnień. Nie da się bezpiecznie odzyskać 100% RAM-u — jądro, sterowniki, usługi i cache nadal go potrzebują.
- Panel nie sprowadza już 18–19 GiB sprzętu do jednej liczby „dostępne”. Pokazuje osobno: pełny fizyczny RAM Lenovo + Redmi, pamięć zajętą przez systemy i aplikacje, natychmiast dostępny RAM, rozmiar zmapowanego GGUF, rzeczywisty resident set procesów YourLM oraz wolny limit zatwierdzeń/pliku stronicowania Windows. Są to różne pomiary, nie jeden wspólny obszar RAM ani obietnica rezydentności wszystkich bajtów naraz. Na Redmi liczymy pamięć fizyczną, **nie** „8 + 8 GB” z rozszerzeniem flash. Profil standardowy używa kontekstu 2048 i jednej sekwencji; bezpośredni Balanced na Androidzie dobiera zachowawczo 2048–8192 według fizycznego RAM.
- **Gemma 4 26B-A4B Abliterated i Mistral Small 3.2 24B Abliterated**: sprawdź *konkretny plik* i obsługę architektury w b12562. Samo 24 mld wag po 4 bity to około 11,2 GiB, **przed** narzutem kwantyzacji, KV i buforów. W MoE mniejsza liczba aktywnych parametrów na token nie oznacza, że można pominąć pamięć pozostałych ekspertów. Nie ma gwarancji załadowania ani użytecznej prędkości. KB10 i Huawei nie są dodawane automatycznie.

## Continue, AnythingLLM i inne klienty OpenAI

Odczytaj **URL `/v1` i klucz** w zakładce **Modele i API** po uruchomieniu serwera. Identyfikator modelu: `yourlm`. Endpointy udostępnia rzeczywisty `llama-server`, m.in. `GET /v1/models` i `POST /v1/chat/completions`. Na tej samej maszynie użyj loopbacku. Na innym komputerze użyj adresu prywatnego hosta wybranego **przed** startem; `127.0.0.1` zawsze oznacza urządzenie klienta.

- **Continue / VS Code:** przycisk „Kopiuj konfigurację Continue” daje konfigurację YAML z odpowiednim adresem i aktualnym kluczem. Wklej wpis `models` do swojej lokalnej konfiguracji Continue (nie nadpisuj innych modeli). Tryb agentowy wymaga obsługi *tool calling* przez konkretny GGUF i szablon rozmowy. Dla takiego modelu dodaj `capabilities: [tool_use]` do jego wpisu i wybierz Agent w Continue. Zacznij od narzędzi tylko do odczytu i zatwierdzaj edycje oraz polecenia. Narzędzia wykonuje Continue; niebezpieczne serwerowe narzędzia plikowe/powłoki `llama-server` są w YourLM jawnie wyłączone. To integracja z istniejącym rozszerzeniem, nie osobna wtyczka. Mały kontekst może ograniczać większe zadania.
- **AnythingLLM:** wybierz kompatybilnego dostawcę OpenAI / Generic OpenAI, podaj URL, klucz i model `yourlm`. Jeśli chcesz w pełni lokalnego RAG, skonfiguruj też lokalny model embeddingów w kliencie. YourLM nie konfiguruje zewnętrznych usług ani telemetrii klientów.

## Prywatność, ograniczenia i diagnostyka

- **RPC jest eksperymentalne.** Surowy RPC nasłuchuje tylko na loopbacku. Między urządzeniami działa tunel TLS z przypiętym odciskiem certyfikatu i sekretem sesji. Przy ręcznym parowaniu 20-znakowy kod ma 100 bitów losowości i nie jest wysyłany przez sieć: host przesyła losowe wyzwanie, worker odpowiada HMAC obejmującym wyzwanie, adres TLS i odcisk certyfikatu, a dopiero potem host otwiera przypięte TLS. Pełny QR przenosi równoważne dane bezpośrednio. Tożsamość parowania (kod, certyfikat TLS i preferowany port mostu) jest przechowywana w prywatnych danych aplikacji, aby host mógł ponownie zweryfikować worker po rekreacji usługi. Zmienia się po wyczyszczeniu danych aplikacji; po zmianie adresu IP użyj aktualnego adresu pokazanego na telefonie. Nie publikuj kodu ani QR. To nie izoluje przed złośliwym oprogramowaniem już działającym na urządzeniu.
- **Zamykanie aplikacji jest zawsze ręczne i łagodne.** Lista obejmuje tylko aplikacje bieżącego użytkownika z widocznymi oknami, największe zwykłe aplikacje są wstępnie zaznaczone, ale można odznaczyć każdą z nich; przed operacją PID, nazwa procesu i status ochrony są sprawdzane ponownie. Program z niezapisanym dokumentem może pokazać własne pytanie i pozostać otwarty.
- **Tunel ADB nie omija zabezpieczeń parowania.** Host dopasowuje urządzenie USB przez przypięty certyfikat i sekret sesji, a benchmark jest dostępny dopiero po uwierzytelnieniu. `adb forward` kończy się na osobnym TLS loopback; natywny RPC nadal słucha tylko na `127.0.0.1` wewnątrz telefonu. Po odłączeniu kabla nowe połączenie może wrócić do Wi-Fi, ale przerwanej w połowie komendy RPC nie można migrować.
- **API LAN to HTTP z kluczem Bearer, nie HTTPS.** Korzystaj wyłącznie w zaufanej prywatnej sieci; nie przekierowuj portów na routerze. Do niezaufanej sieci potrzebny jest osobny bezpieczny transport. Panel zarządzania nie jest wystawiany w LAN. Klucz API zmienia się po każdym uruchomieniu modelu. Historia w panelu pozostaje w pamięci karty, a silnik zapisuje lokalny log diagnostyczny; zewnętrzne klienty mogą przechowywać własną historię.
- Jeśli parowanie nie działa: sprawdź wspólne Wi-Fi, brak izolacji klientów/Guest Wi-Fi, prywatny IPv4 oraz aktualny adres i kod pokazany na telefonie. Przepisz wszystkie cztery grupy kodu; nie wpisuj pełnego `YLM1|…` w pole krótkiego kodu. Kamera laptopa jest tylko opcją. Zapora Windows powinna dopuszczać połączenia wyłącznie w profilu prywatnym. Android szuka interfejsu Wi-Fi `wlan*`.
- Pasek ładowania pokazuje osiągnięty etap, nie obiecuje dokładnej ETA. Gdy rośnie licznik odczytu, czasu CPU albo transferu RPC, panel wprost zaleca dalsze czekanie. Po co najmniej trzech minutach i minucie bez żadnej mierzalnej aktywności proponuje zatrzymanie oraz próbę bez workera. Pełny `engine.log` pozostaje dostępny pod paskiem do diagnostyki.
- `Remote RPC server crashed or returned malformed response` oznacza przerwane połączenie z procesem workera podczas komendy RPC, a nie błąd ostrzeżenia mmap. Cache nie tworzy dodatkowej pełnotensorowej alokacji, wpisy są publikowane atomowo, a RC12 pozostawia co najmniej 2048 MiB i zwiększa zapas według największego tensora modelu. Podczas ładowania Windows co 3 sekundy pobiera uwierzytelnioną migawkę Redmi: kod i czas zakończenia procesu natywnego, RAM, miejsce, cache, Wi-Fi, błędy mostu Java, historię zakończeń Androida oraz końcówkę szczegółowego logu RPC. Po awarii próbuje pobrać raport końcowy, a gdy cały listener telefonu już zniknął, automatycznie dołącza ostatnią udaną migawkę do `engine.log`. Przycisk **Kopiuj diagnostykę** nadal kopiuje jeden wspólny raport.
- Przerwanej komendy RPC ani trwającego ładowania `llama-server` nie można wznowić w połowie, ponieważ po wyjściu procesu znikają jego tensory i stan protokołu. Android automatycznie odtwarza jednak proces w ograniczonym budżecie, pozostawia endpoint diagnostyczny oraz przygotowuje worker do kolejnego startu modelu. Gdy bieżąca sesja hosta już się zakończyła, uruchom model ponownie; nie ma migracji trwającej generacji na inny węzeł. Worker Android działa jako usługa pierwszoplanowa przy wyłączonym ekranie; nie usuwaj jego stałego powiadomienia i nie używaj systemowej opcji „Wymuś zatrzymanie”. Cache RPC może zajmować kilka GiB prywatnej pamięci telefonu. Zapisz model na hoście z odpowiednim zapasem miejsca. Podczas ładowania bardzo dużych plików system nadal może przerwać proces, jeśli naprawdę wyczerpie zasoby.
- Program Windows: `%LocalAppData%\Programs\YourLM\YourLM.exe`; skrót znajduje się w Menu Start, a wpis odinstalowania w ustawieniach bieżącego użytkownika. Dane Windows: `%AppData%\YourLM\` (`models`, ustawienia, log i wersjonowane `components`). Aktualizacja podmienia tylko zainstalowany EXE; modele i konfiguracja pozostają. Odinstalowanie również celowo zachowuje prywatne dane. Runtime, ADB oraz instalacyjny APK są odzyskiwane z pliku wydania, a zmienione komponenty są odtwarzane przed użyciem.
- EXE nie ma komercyjnego podpisu Authenticode. Ma jawne informacje wersji, manifest `asInvoker` i nie wymaga administratora. Od 0.2.0-rc1 APK używa stałej tożsamości aktualizacji projektu (certyfikat SHA-256 `bb2639f3d49a2d7db0845884e76d6bb51152a6e9c0df92fcfe885a26c5de94a6`), przeznaczonej do wszystkich następnych wydań. Weryfikuj sumy plików. Jeśli antywirus zgłosi alarm, nie zezwalaj ani nie dodawaj wyjątku — zgłoś pełną nazwę detekcji i SHA-256. Własny build podpisany innym kluczem wymaga odinstalowania poprzedniego APK (to usuwa prywatne kopie modeli). Wagi źródłowe zachowaj osobno.
- W tej wersji nie ma generowania obrazów, Vision ani obsługi wieloczęściowych GGUF. Publiczny jednoplikowy GGUF można wyszukać i pobrać z Hugging Face; prywatne/gated repozytoria nie są omijane, a modele lokalne nadal działają. CI sprawdza instalację per-user, skrót Menu Start, wpis Zainstalowanych aplikacji, uruchomienie i odinstalowanie na Windows; nadal potrzebne są testy na fizycznym Lenovo i Redmi.

## Testy i budowanie

Kod hosta: Go, statycznie osadzony interfejs bez CDN oraz czysto-gościowy host WebView2 z osadzonym loaderem. Android: natywna Activity i foreground service w Javie, stabilne binarki CPU/RPC, osobny pager ARM64 i ten sam panel hosta w WebView. Licencje komponentów są w `licenses/`, `host/web/` i źródłach vendora.

```sh
go test ./...
git clone https://github.com/ggml-org/llama.cpp /tmp/yourlm-llama
git -C /tmp/yourlm-llama checkout c0b97be0b297177a88df08e96c01420976bb18d0
LLAMA_SRC=/tmp/yourlm-llama tests/rpc-cache-smoke.sh
LLAMA_SRC=/tmp/yourlm-llama scripts/build-windows.sh
```

Skrypty przed kompilacją stosują do dokładnie przypiętego b12562 audytowalną poprawkę `patches/llama-rpc-streaming-cache.patch`. Osobny `scripts/build-smol-android.sh` wymaga llama.cpp v0.8.0 `8642541…` i weryfikuje SHA-256 niezmienionej poprawki smolmaxxing `8d12bb1`; nigdy nie nakłada jej na b12562. Budowanie zostaje przerwane, jeśli patch nie pasuje albo źródło ma inny commit.

Windows wymaga Go 1.25.5, Zig 0.14.1, CMake i Ninja oraz gotowego `packages/YourLM-Android-arm64.apk`. Skrypt buduje dwa statyczne programy runtime ze źródła i osadza je wraz z przypiętym minimalnym ADB oraz APK w jednym `packages/YourLM.exe`. Kontroler weryfikuje runtime przed uruchomieniem. Manifest oraz metadane PE są generowane z `windows/`; po zmianie wersji uruchom `scripts/regenerate-windows-resource.sh`. Szczegółowy opis zachowania i granic zaufania znajduje się w [SECURITY.md](SECURITY.md).

APK (Linux x64): Go 1.25.5, CMake, Make, JDK 17, Android SDK platform/build-tools 34, `zip` oraz **oficjalny Android NDK 27.2.12479018**. Androidowych silników nie wolno budować jako ogólne `aarch64-linux-musl`: skrypt wymaga sysrootu NDK, ABI `arm64-v8a`, API 28 i statycznego C++ runtime. Skrypty niczego nie pobierają i nie zawierają klucza podpisującego.

`verify-android-elf.sh` zatrzymuje pakowanie, jeśli którykolwiek wykonywalny payload wydania nie jest AArch64 `ET_DYN` PIE z `/system/bin/linker64`, zawiera `TEXTREL`/RPATH albo wymaga niedołączonego `libc++_shared.so`. Aplikacja powtarza podstawową kontrolę nagłówka ELF przed startem i pokazuje kod wyjścia oraz końcówkę natywnego logu zamiast ogólnego komunikatu.

CI osobno buduje i kontroluje dokładne payloady ARM64 wydania, a test inferencji, workera, parowania i hosta wykonuje na równoważnym buildzie x86_64 w sprzętowo przyspieszonym emulatorze. Hostowany runner x86_64 nie uruchamiał programowego emulatora ARM64 nawet w 30 minut, dlatego wynik x86_64 nie zastępuje testu gotowego APK na fizycznym telefonie ARM64.

Testy jednostkowe obejmują metadane GGUF, zgodność receptury Q2/Q4, metadata-gating i stałą allow-listę profilu pagera, budżety, bezpieczną selekcję/protekcję procesów i ponowne użycie PID, filtrowanie fizycznych urządzeń ADB, ważony wybór transportu i rzeczywisty dwukierunkowy benchmark TLS, zakresowe pobieranie/wznawianie/anulowanie/SHA-256, walidację kodów, granice panelu oraz odrzucenie złego sekretu i certyfikatu. Opcjonalny test integracyjny:

```sh
python3 tests/tiny_model.py /tmp/yourlm-test.gguf
# Uruchom przypięty ggml-rpc-server na 127.0.0.1:50052, tylko na czas testu.
TEST_ENGINE=/sciezka/do/llama-server TEST_MODEL=/tmp/yourlm-test.gguf \
TEST_RPC=127.0.0.1:50052 go test -v -run TestRealCluster ./host
```

W środowisku budowania wykonano inferencję syntetycznego GGUF z dwoma procesami ARM64 pod QEMU, przez rzeczywisty tunel TLS, z 2 z 4 warstw na workerze. Uzyskano odpowiedź `/v1/chat/completions`; osobno sprawdzono odrzucenie zapytania bez klucza (401). **To test ścieżki wykonania, nie jakości modelu ani szybkości fizycznego klastra.**
