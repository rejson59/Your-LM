YourLM 0.2.0-rc17 — Windows x64 + Qwen3.6 Balanced Phone

Uruchom pobrany pojedynczy YourLM.exe jako zwykły użytkownik. Na Lenovo z dużym, zapisywalnym dyskiem stałym D: RC17 instaluje program bez administratora w D:\YourLM\App, a modele, runtime llama.cpp, minimalny ADB, APK, cache, logi, raporty i aktualizacje w D:\YourLM\Data. Dotychczasowe dane z %AppData%\YourLM są kopiowane przez nieaktywny Data.migrating. Pozostawiony `.migrating-part` jest sprawdzany bajt po bajcie i wznawiany, a pełne pliki oraz końcowe drzewo są weryfikowane SHA-256 przed publikacją i usunięciem źródła. Blokada systemowa wyklucza jednoczesną migrację z dwóch okien i nie zostaje na stałe po awarii. Odświeżony panel Testy → Magazyn pokazuje osobno aktywny dysk, odzyskane pliki/bajty, zachowanie źródła, zalecane działanie i rozwijane szczegóły błędu. Data.migrating nigdy nie jest aktywną biblioteką. Skrót Menu Start i wpis Ustawienia → Aplikacje → Zainstalowane aplikacje są aktualizowane automatycznie; na C: pozostają tylko ich małe metadane. Gdy D: nie ma co najmniej 128 GiB pojemności i 64 GiB wolnego miejsca albo nie przejdzie kontroli zapisu, program zachowuje bezpieczny fallback w profilu Windows. Panel otwiera się w natywnym oknie WebView2; przeglądarka jest używana tylko awaryjnie. Parametr --portable pomija instalację.

W zakładce Testy podłącz odblokowany Redmi z zaakceptowanym debugowaniem USB i uruchom pełny test. YourLM lokalnie odczyta dokładny model Lenovo, Windows, CPU, RAM i GPU, zmierzy własny katalog na D:, odczyta model/SoC/fizyczny RAM/UFS Redmi i porówna sparowane Wi-Fi z szyfrowanym tunelem USB. RC17 scala inwentaryzację ADB i sparowanego workera tego samego `24090RA29G`, zamiast pokazywać drugi pusty rekord z prefiksem Xiaomi. Po uruchomieniu modelu osobna krótka próba dopisze tokeny/s i sprawdzi wykonanie dokładnej instrukcji. Raport nie zawiera numeru seryjnego USB, kodu parowania ani klucza API. Autopilot steruje wyłącznie własnymi testami, plikami i wyborem audytowanego profilu; nie dostaje dowolnej powłoki ani dostępu do dokumentów.

W zakładce Telefon USB podłącz odblokowany telefon z włączonym debugowaniem USB i użyj przycisku Zainstaluj lub zaktualizuj. `adb install -r` zachowuje prywatne dane aplikacji. Po każdej aktualizacji EXE wykonaj ten krok ponownie — aplikacja Windows nie podmienia samoczynnie APK już zainstalowanego na telefonie.

Jeśli po sparowaniu workera kabel z autoryzowanym debugowaniem pozostaje podłączony, YourLM tworzy lokalny `adb forward` do szyfrowanego mostu TLS telefonu. Przed startem modelu przesyła próbkę 4 MiB w obie strony przez USB i Wi-Fi, pokazuje oba wyniki i automatycznie wybiera lepszy wynik ważony pod duży transfer host → worker; przy różnicy do 5% rozstrzyga niższy ping. Drugie łącze pozostaje awaryjne. Surowy RPC nie jest wystawiany przez ADB, a odłączenie kabla podczas trwającej komendy nadal może przerwać sesję. USB 2.0 nie musi być szybsze od dobrego Wi-Fi 5 GHz i nie zwiększa mocy CPU telefonu.

Wbudowany czat przesyła odpowiedź na żywo zamiast czekać na wygenerowanie całego tekstu. Domyślny limit szybkiej próby to 64 tokeny; można wybrać 128, 256 lub 512 oraz zatrzymać bieżącą odpowiedź bez wyłączania modelu. Duży model 24–26B na CPU nadal może działać poniżej 1 tokena/s. Jeśli log zawiera `removing it from EOG list`, konkretny GGUF ma podejrzane metadane końca odpowiedzi i może dochodzić do limitu za każdym razem.

W Urządzenia → Odzyskaj pamięć przed modelem Windows pokazuje zwykłe aplikacje bieżącego użytkownika z widocznymi oknami i ich przybliżony RAM. Największe bezpieczne pozycje są zaznaczone wstępnie; odznacz każdą aplikację, której nie chcesz zamykać. Po zapisaniu pracy wyślij wybranym pozycjom standardowe WM_CLOSE; YourLM nigdy nie wymusza zakończenia procesu. System, antywirus, instalatory, terminale, sesje administratora oraz sam YourLM są chronione. Wynik pokazuje aplikacje zamknięte, pozostałe i przybliżony wzrost dostępnego RAM-u. Nie da się bezpiecznie odzyskać 100% pamięci systemu.

W Model i API program proponuje jeden środek: Qwen3.6-35B-A3B Abliterated Balanced Q2/Q4. Pobiera tylko potrzebne zakresy przypiętych źródeł Huihui, wymaga zgodnych metadanych/tokenizera i pełnego schematu tensorów, układa ekspertów na końcu, zachowuje części po zatrzymaniu i oblicza SHA-256 gotowego GGUF. Abliteracja oznacza ograniczenie wyuczonych odmów, nie większą inteligencję. Inny publiczny lub lokalny jednoplikowy GGUF można nadal wybrać ręcznie. Inferencja i prompty pozostają lokalne.

Worker Android działa jako usługa pierwszoplanowa z blokadą CPU i Wi-Fi. Po uruchomieniu może dalej pomagać laptopowi przy wyłączonym ekranie i zamkniętym widoku aplikacji; zatrzymasz go z powiadomienia lub aplikacji. Jawne zatrzymanie jest trwałe. Nieoczekiwane wyjście procesu natywnego zachowuje diagnostykę i uruchamia najwyżej trzy próby z opóźnieniami 1/5/15 s, bez nieskończonego przeładowywania modelu. Prywatny cache RPC zachowuje przydzielone tensory i znacząco przyspiesza kolejne uruchomienia tego samego modelu. Cache jest strumieniowany porcjami do 16 MiB i odrzuca wpisy niepełne lub uszkodzone, zamiast tworzyć w RAM dodatkową kopię całego tensora. RC12 pobiera z Redmi migawkę diagnostyczną co 3 sekundy podczas ładowania. Jeśli po awarii listener telefonu zniknie, jeden raport kopiowany w Windows zawiera ostatnią udaną migawkę, w tym błędy mostu Java i końcówkę szczegółowego logu natywnego.

Panel pamięci pokazuje osobno pełny fizyczny RAM, użycie systemów, RAM dostępny teraz, zmapowany plik GGUF, rzeczywistą alokację silników oraz limit zatwierdzeń/pliku stronicowania Windows. Dostępne teraz nie jest limitem rozmiaru GGUF. YourLM nie odrzuca 12,4 GiB modelu statycznym planistą: host próbuje mmap, a worker używa natywnego podziału llama.cpp z rezerwą szczytu ładowania wyliczaną z największego tensora (minimum 2048 MiB) dla Androida i RPC.

Podczas startu modelu panel pokazuje potwierdzony etap, czas oraz rzeczywistą aktywność dysku, CPU i RPC. Etapy są orientacyjne, a nie udawanym procentem tensorów. Po dłuższym braku wszystkich mierzalnych sygnałów panel podpowiada, kiedy rozsądnie zatrzymać próbę.

Modele, ustawienia, cache i dane aplikacji pozostają poza EXE i są zachowywane przy aktualizacji.
